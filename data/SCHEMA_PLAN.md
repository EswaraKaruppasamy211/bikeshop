# Phase 1 data and module plan

No database connection or migration was run for this phase. Keep the existing
Supabase URL and credentials unchanged.

## Existing schema coverage

| Module | Existing tables | Use |
| --- | --- | --- |
| Product inventory and details | `products`, `product_images`, `product_compatibility` | Public API reads only active products with positive quantity and explicitly public image references; compatibility results include only administrator-verified fits. |
| Categories | `product_categories` | Public category list and product category filtering. |
| Make/model catalogue | `vehicle_makes`, `vehicle_models` | Product compatibility lookup and future configurable vehicle catalogue. |
| Vehicle purchase enquiries | `vehicle_purchase_enquiries`, `enquiry_images` | Validated public submissions; private image storage is not yet configured. |
| Contact enquiries | `contact_enquiries` | Validated contact messages. |
| Authentication reference | `profiles` | Role/profile reference only. It is not an authentication system and must be integrated with Supabase Auth (or another tested provider) before admin access. |
| Assessment records | `ai_assessments`, `ai_assessment_findings`, `ai_assessment_images` | Future provider-backed, image-supported assessments only. No assessment is generated by this phase. |
| Business settings and audit | `business_settings`, `audit_logs` | Reserved for authenticated admin-managed settings and audit trails. |

The schema already represents these entities; no duplicate tables are needed.
The first enquiry migration adds only the free-text make/model/fuel fields and
optional contact email used by public forms. It is additive and uses
`IF NOT EXISTS`; apply it only after confirming migration state.

## Planned backend boundaries

- `routes/`: HTTP paths and request middleware.
- `controllers/`: validation, HTTP status codes, and response shapes.
- `services/`: parameterized database operations.
- `validation/`: Zod request/query schemas.
- `database.ts`: backend-only PostgreSQL pool and reachability checks.

Product and category reads use the existing inventory tables. Public enquiry
routes write only the public form fields; admin notes and status are never
accepted from clients. Admin product operations use provisioned backend
credentials and protected routes; the current administrator identity is not
mapped to a `profiles` row, so audit actor IDs are NULL. Image upload is not
enabled until a private object-storage provider, MIME/content verification,
limits, and signed access are implemented. AI assessment status stays
unavailable until a real vision provider and safe image pipeline are configured.

Before production, implement and test Supabase Auth token verification, strict
admin authorization, row-level access controls/grants, rate limits appropriate
to deployment, private storage and retention/deletion rules, and migration
tracking. Do not expose a service-role or database credential to the browser.
